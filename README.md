# Crew-cal

승무원 스케줄을 달력으로 관리하는 정적 웹 앱. 빌드 도구나 의존성 없이 `index.html` 만 열면 동작한다.

## 입력 방식 3가지

### 1. 날짜별 입력
날짜 · 코드 · 구간 · 출발/도착 시각 · 메모를 하나씩 입력한다. 코드가 편명이면 라벨이 **출발/도착**,
그 밖의 근무면 **시작/종료** 로 바뀐다. 도착이 다음 날이면 `도착이 익일` 을 체크한다. 달력에서 날짜를 누르면 그 날짜가 바로 폼에 잡히고,
아래에 해당 날짜의 일정 목록이 나와 개별 삭제도 가능하다.

### 2. 텍스트 붙여넣기
크루넷에서 복사한 스케줄 텍스트를 그대로 붙여넣으면 날짜 · 코드 · 구간 · 출발/도착 시각을 파싱해 **미리보기**로 보여주고,
확인을 눌러야 달력에 반영된다. 반영 시 해당 날짜의 기존 일정을 덮어쓸지, 이어 붙일지 고를 수 있다.

파서(`src/parser.js`)가 받아들이는 형태:

| 종류 | 예 |
| --- | --- |
| 연-월-일 | `2026-09-06`, `2026.09.06`, `2026/09/06`, `20260906` |
| 월-일 (연도는 기준 연·월로 보정) | `09/06`, `9-6` |
| 한글 | `2026년 9월 6일`, `9월 6일`, `6일` |
| 영문 월 | `06SEP26`, `07 SEP`, `SEP08` |
| 줄 앞의 일자 | `01\tKE0035` |
| 날짜 범위 | `2026-09-10 ~ 2026-09-12 VAC` |
| 날짜 줄 + 코드 줄 | 날짜만 있는 줄 다음의 코드 줄들이 그 날짜에 붙는다 |
| 한 줄에 여러 날 | `5 KE0038 TVL 6 ATDO` 처럼 한 줄에 여러 날이 있어도 날짜별로 나눈다 |
| 격자에 딸린 옆 달 | 달력 앞뒤에 흐리게 붙어 오는 지난달·다음 달 날짜를 제 달로 보낸다 |

- 코드: 항공편(`KE0035`, `KE 0035`, `KE-035`)과 근무 코드(`LO`, `ATDO`, `STBY`, `DO`, `VAC`, `GT` …)
- 구간: `ICN/JFK`, `ICN-JFK`

출발·도착 시각은 이런 형태를 모두 읽고, 그 줄의 항공편(없으면 직전 근무)에 붙는다:

| 종류 | 예 | 결과 |
| --- | --- | --- |
| 범위 | `1030-1420`, `09:30-14:20` | 출발 10:30 · 도착 14:20 |
| 익일 도착 | `2350-0620+1`, `2350-0620 +1` | 출발 23:50 · 도착 06:20 (익일) |
| 라벨 | `STD 1420 STA 0850+1`, `DEP 09:30 ARR 18:40`, `DEP1030 ARR:1420` | 라벨대로 출발/도착 |
| 한글 라벨 | `출발 09:30 도착 18:40` | 라벨대로 출발/도착 |
| 표 형태 | `KE0035	ICN/JFK	1030	1420` | 앞 숫자가 출발, 뒤가 도착 |
| 한쪽만 | `STA 1420` | 도착만 채움 |

- `STD/ETD/ATD/DEP/OUT/출발` 은 출발, `STA/ETA/ATA/ARR/IN/도착` 은 도착으로 본다
- 라벨 없이 시각이 두 번 나오면 앞이 출발, 뒤가 도착이다
- 편명 없는 줄의 3~4자리 숫자(`9999` 같은 시각이 아닌 값 포함)는 시각으로 잡지 않는다
- 비행이 아닌 근무(`STBY 0900-1700` 등)에서는 같은 값을 **시작/종료** 로 읽어 표시한다
- 구분자는 공백 · 탭 · 쉼표 · 파이프 무엇이든 되고, 요일 표기 `(일)` `[MON]` 과 표 머리글은 무시한다
- 사전에 없는 코드는 버리지 않고 **미확인**으로 표시한 뒤 미리보기에서 기본 해제 상태로 둔다 (체크하면 그대로 반영)
- 날짜를 못 찾은 줄은 경고 목록에 남긴다

근무 코드 사전은 `src/codes.js` 에 있다. 코드를 추가하려면 이 파일에 한 줄 넣으면 달력 색과 라벨까지 함께 붙는다.

### 2-1. Claude로 정리

사진 앱의 텍스트 인식으로 복사한 글이나 화면을 통째로 복사한 글은 달력 격자가 풀려 줄이 뒤섞인다.
붙여넣기 탭의 **Claude로 정리** 를 누르면 그 글을 날짜 + 코드 형식으로 다시 맞춰 미리보기에 태운다.
아티팩트에서 Claude 호출이 되는 화면에서만 버튼이 보인다. 이미지 전송이 막힌 화면에서도
텍스트 호출은 되는 경우가 많아, 스크린샷 인식을 못 쓰는 환경의 우회로가 된다.

### 3. 스크린샷 업로드
스케줄 화면을 캡처해서 올리면 날짜 · 코드 · 구간 · 출발/도착 시각을 읽어온다.
달력 형태(칸마다 날짜와 근무)든 한 줄에 하루씩인 목록이든 처리한다.
읽은 결과는 바로 반영하지 않고 **텍스트 붙여넣기 미리보기로 넘겨서** 확인·수정한 뒤 반영한다.

`src/vision.js` 가 두 경로를 자동으로 고른다.

| 경로 | 언제 | 준비물 |
| --- | --- | --- |
| `sample` | Claude 아티팩트로 열었을 때 | 없음. 보는 사람의 Claude 가 직접 읽는다 (첫 호출 때 사용 동의) |
| `endpoint` | 앱을 직접 띄워 쓸 때 | 아래 규약을 지키는 서버 주소 |

어느 쪽도 못 쓰면 버튼이 잠기고 텍스트 붙여넣기를 안내한다.
읽는 데 10~60초쯤 걸리고, 진행 중에는 같은 버튼이 중지 버튼이 된다.

브라우저에 API 키를 두면 그대로 노출되므로, 직접 띄워 쓸 때도 키는 서버에 두고
앱에는 서버 주소만 넣는다 (스크린샷 탭 → "이미지 인식 API 연동 설정").

서버가 지켜야 할 규약:

```
POST {endpoint}
요청  { image_base64, media_type, prompt, model, hint: { year, month } }
응답  { text }     // "YYYY-MM-DD<탭>코드 …" 형식 → 텍스트 파서로 넘어감
   또는 { entries: [{ date, code, route?, start?, end?, endOffset? }] }
```

`entries` 로 응답할 때 시각은 `start`/`end`(또는 `dep`/`arr`)와 익일 도착을 뜻하는 `endOffset: 1` 로 준다.
이미지에 보낼 프롬프트는 `vision.buildPrompt({year, month})` 가, Claude Messages API 요청 본문은
`vision.buildClaudeRequest()` 가 들고 있다.

## 보기 방식

달력과 목록 모두 크루넷처럼 **앞뒤 달 날짜를 함께** 보여준다. 지난달 말일과 다음 달 초를
흐리게 붙여 그리므로, 31일 비행 다음 1일 체류처럼 달을 넘겨 이어지는 일정이 잘리지 않는다.

| 보기 | 쓰임 |
| --- | --- |
| 달력 | 한 달 배치를 통으로 본다. 칸에 코드와 `10:30→14:20`(익일 도착이면 `23:50→06:20+1`)이 보인다 |
| 목록 | 일정 있는 날만 날짜 · 코드 · 구간 · 출발/도착 시각으로 편다. 칸이 좁은 폰에서 훑기 좋다 |
| 연간 | 열두 달을 작게 늘어놓고 그날 성격을 색으로만 찍는다. 휴가 계획을 짜거나 어느 달이 빡셌는지 볼 때. 폰에서도 한 해가 한 화면에 들어온다 |

연간 보기에서는 머리말 화살표가 달 대신 해를 넘기고, 날짜를 누르면 달력으로 돌아가 그 날을 편다.

한 달 요약은 **비행을 편수로, 나머지를 날수로** 센다. "체류 3" 이 사흘인지 세 번인지
알 수 없던 걸 고친 것이다. 그 달에 다녀온 도시도 한 줄로 붙는다.

훑어봤을 때 **쉬는 날과 비행 날이 바로 갈리도록** 칸 전체를 그날의 성격대로 옅게 칠한다
(`calendar.dayCategory`). 칩만으로는 크기가 다 비슷해 한눈에 구분되지 않는다는 이야기가
있었다. 하루에 여러 개가 있으면 무거운 쪽을 따르므로, 비행이 하나라도 있으면 비행하는
날이고 휴무만 있어야 쉬는 날이다. **비행과 체류는 같은 색**을 쓴다. 한 번 나가면
돌아올 때까지가 한 덩어리이므로, 출발일부터 도착일까지 같은 색으로 이어져 보인다.
목록 보기에서는 같은 색을 왼쪽 띠로 세운다.

칸 안에서는 **도시가 주인공**이다. 국기와 도시 이름을 큰 글씨로 놓고 그 아래에 시각을,
맨 아래에 원래 코드를 작게 적는다(`KE0035`, `ATDO`). 체류하는 날에는 구간이 안 적혀
있지만 `calendar.tripPlaces` 가 마지막으로 내린 공항을 다음 비행까지 이어 주므로,
체류 중인 날에도 어느 도시에 있는지 그대로 보인다.

고른 보기는 브라우저에 저장돼 다음에 열 때도 유지된다.
하루치 일정은 출발 시각 순으로 정렬된다.
달력 칸에는 **출발하는 나라 국기 · 코드 · 한국 기준 시각**이 보인다.
시차가 섞이면 헷갈리므로 한국 시각만 남긴다. 한국에서 떠나는 편은 `09:45 출발`,
한국으로 오는 편은 `17:50+1 한국 도착` 만 쓴다. 어느 나라 시각인지 헷갈리지 않게
도착 쪽에는 "한국" 을 붙여 둔다. 국내선(`ICN/PUS`)이나 한국과 무관한 구간,
구간을 모르는 경우에는 양쪽을 함께 보여준다.
체류(`LO`)에는 시각을 쓰지 않는다. 며칠에 걸쳐 이어지는 상태라 특정 시각이 뜻이 없기 때문이다.
대기(`STBY`)처럼 시각이 뜻을 갖는 근무는 그대로 보여준다.

감춘 시각도 지우지 않고 그대로 갖고 있어서, 코드를 길게 누르면 뜨는 설명과
"기억한 편명" 목록에는 출발·도착이 모두 나온다.
칸이 좁으면 도착 시각이 아랫줄로 접히고, 편명은 항공사 코드를 떼어 번호만 남긴다
(`🇰🇷 KE0035` → `🇰🇷 0035`). 전체 코드와 나라 이름은 길게 누르면 뜨는 설명과 목록 보기에 남는다.

## 공휴일

달력에 한국 공휴일을 빨갛게 표시한다(`src/holidays.js`). **2020~2100년**이 들어 있다.

날짜가 고정된 공휴일(신정·삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절)은
어느 해든 그대로 쓴다. 설날·부처님오신날·추석은 음력이라 `scripts/make-holidays.js` 가
음력 계산으로 뽑아 `src/holidays-lunar.js` 에 넣어 둔다.

```bash
npm run holidays          # 기본 2020~2100
node scripts/make-holidays.js 2020 2200
```

음력 계산은 삭(합삭)의 순간을 Meeus 의 주기항으로, 중기(태양 황경이 30도의 배수가 되는
순간)를 저정밀 태양 황경 공식으로 구한다. 달의 시작은 삭이 든 날, 윤달은 중기가 없는
첫 번째 달이며, 날짜는 모두 한국 표준시 자정으로 가른다. 만들 때마다 이미 아는 해
(2020~2027년의 설날·부처님오신날·추석 24일)와 대조해서 하나라도 어긋나면 만들지 않는다.

연휴(설·추석 앞뒤 하루)와 대체공휴일은 표에 넣지 않고 규칙으로 계산한다.

- 삼일절·광복절·개천절·한글날·부처님오신날·성탄절이 토·일과 겹치면 다음 첫 비공휴일
- 어린이날은 토·일과 겹치거나 다른 공휴일과 겹치면 대체
- 설날·추석 연휴 사흘에 일요일이 끼면 하루 대체
- 신정과 현충일은 대체하지 않는다

지금 시행되는 규칙(2023년 이후)을 그대로 적용하므로, 규칙이 달랐던 2022년 이전은
실제와 다를 수 있다. 임시공휴일과 선거일은 미리 알 수 없어 정해진 것만 `EXTRA` 에 적는다.
표 밖의 해를 보고 있으면 없는 날을 지어내는 대신 달력 아래에 그렇다고 적어 준다.

## 다음 근무와 체류지 시각

머리말 아래 띠에 오늘부터 가장 가까운 일정이 뜬다. 하루에 여럿이면 비행을 앞세우고,
누르면 그 날로 넘어간다(`calendar.upcoming`).

해외에 있는 날을 고르면 달력 아래에 **시차 배너**가 뜬다. 현지 시각과 한국 시각을
나란히 놓고, 그 위에 시차(`한국보다 7시간 느림`)를 적는다. 시계는 1분마다 다시 그린다.

"지금 어디에 있나" 는 그날 일정만으로는 알 수 없다. 체류하는 날에는 구간이 없기
때문이다. 그래서 그 날짜에서 이레까지 거슬러 올라가며 가장 가까운 비행을 찾고,
그 편이 **내린 공항**을 지금 있는 곳으로 본다. 한국에 내렸으면 배너를 띄우지 않는다.

`airports.zoneOf` 가 공항을 IANA 시간대 이름으로 바꾸고, 나머지 계산은 `src/clock.js`
가 맡는다. 서머타임은 나라마다 다르고 해마다 바뀌므로 직접 세지 않고 브라우저의
시간대 자료(`Intl.DateTimeFormat`)를 읽는다. 30분 단위 시차(인도·네팔)와 날짜가
하루 어긋나는 경우도 담아낸다. 나라별 기준 시간대를 두고, 미국·캐나다·러시아·호주·
인도네시아·멕시코처럼 안에서 갈리는 공항만 따로 덮어쓴다.

## 지난 일정 찾기

달력 위 칸에 편명·도시·코드·날짜 조각을 넣으면 최근 것부터 찾아 준다(`calendar.search`).
KE0035 는 `ke35`, `35`, `애틀랜타`, `ATL`, `2026-07` 어느 쪽으로도 걸린다.

## 캘린더 앱에 넣기 (.ics)

**캘린더 앱에 넣기** 를 누르면 보고 있는 달이 `.ics` 파일로 나온다(`src/ics.js`).
아이폰은 그 파일을 열면 캘린더에 추가할지 물어본다.

- 시각은 `Asia/Seoul` 로 못 박는다. 해외에서 열어도 같은 순간을 가리킨다.
- 한국 출발편은 출발 시각부터, 한국 도착편은 실제 내리는 날의 도착 시각부터 한 시간.
  (현지 시각을 갖고 있지 않으니 길이를 지어내지 않는다)
- 체류·휴무처럼 시각이 없는 근무는 하루 종일 일정.
- 크루넷이 이틀에 걸쳐 적어둔 도착편은 달력과 같은 규칙으로 한 번만 넣는다.
- 같은 달을 다시 넣어도 겹치지 않도록 날짜·코드로 고정된 UID 를 쓴다.

## 색

베이지 · 갈색 · 에토프 · 네이비를 바탕으로 한 낮은 채도의 색을 쓴다.
쨍한 색을 칸에 옅게 깔면 파스텔이 튀어 촌스러워 보인다.

| 근무 | 색 | 비고 |
| --- | --- | --- |
| 비행 · 체류 | 네이비 | 나갔다 돌아올 때까지 한 색으로 이어진다 |
| 휴무 | 에토프 베이지 | |
| 휴가 | 올리브 | `VAC` `YVS` `ANL` 은 휴무와 다른 분류(`vacation`)로 읽는다 |
| 교육 | 테라코타 | |
| 대기 | 머스타드 | |
| 미확인 | 딥 브릭 | |

색조가 서로 다른 다섯 갈래(파랑·초록·주황·노랑·무채색)라, 칸을 옅게 깔아도
쉬는 날과 비행 날, 휴가와 교육이 갈려 보인다. 색마다 눈에 들어오는 정도가
달라 칸 배경의 진하기는 13~18%로 조금씩 다르게 준다.

## 도시와 국기

`src/airports.js` 가 공항 코드(IATA) 415개를 나라와 도시 이름으로 옮긴다. 국기는 나라 코드
두 글자를 리저널 인디케이터로 바꿔 만들기 때문에 이미지 파일도 외부 요청도 없다.

달력과 목록에는 그 비행이 **어디 가는 편인지**를 적는다. 한국에서 나가면 도착지,
한국으로 들어오면 출발지가 기준이라 나가는 편과 돌아오는 편에 같은 도시가 찍힌다
(`ICN/ATL` 도 `ATL/ICN` 도 🇺🇸 애틀랜타). 국내선은 도착지를 쓴다.
모르는 공항은 국기 없이 공항 코드를 그대로 보여준다. 취항지를 늘리려면 이 파일의
나라별 목록과 도시 이름 표에 줄을 더하면 된다.

## 화면

iOS 시스템 색·간격·모서리에 맞춰 꾸몄다. 색은 모두 `styles.css` 맨 위 토큰에 모아 두었고
다크 모드는 토큰만 바꿔 끼운다. 근무 칩은 채도 높은 배경 대신 iOS 배지처럼 연한 틴트에
같은 색 글씨를 쓰고, 탭과 달력·목록 전환은 세그먼티드 컨트롤, 헤더는 반투명 블러,
알림은 iOS HUD 모양이다.

## 기본 시간표와 편명 기억

크루넷 월간 화면에는 편명만 있고 시각이 없다. 그래서 두 겹으로 채운다.

`src/schedule.js` 에 대한항공 340편의 구간과 시각이 들어 있어, 등록 없이도 코드만 넣으면
도시 · 국기 · 시각이 붙는다. 국내 공항(인천 · 김포 · 부산 · 제주 · 대구 · 광주 · 청주 · 여수 · 울산 · 사천)의
출발·도착 전광판을 하루치 훑어 모은 값과 개별로 확인한 값이다
(2026-09-06 운항 기준, 코드셰어 KE5xxx 와 화물편 제외).
같은 편이 두 공항 전광판에 걸쳐 나오면 시각을 합쳐, 국내선은 출발·도착을 모두 갖는다. 앱은 한국 쪽 시각만 보여주므로 표에도 한국 쪽 시각만 둔다.

- 한국에서 나가는 편은 **출발 시각**, 한국으로 오는 편은 **한국 도착 시각**
- 확인하지 못한 시각은 비워 둔다. 지어내지 않는다. 대신 붙여넣기 미리보기가
  **한국 쪽 시각을 모르는 편명**을 짚어주므로, "편명 시각"에 한 줄 등록하면 다음부터 자동으로 붙는다
- 표에 없는 편명은 짝이 되는 편의 구간을 뒤집어 **구간만** 쓴다. 짝수는 앞 홀수 편의 복편으로
  (`KE0037 ICN/ORD` 이면 `KE0038` 은 `ORD/ICN`), 홀수는 뒤 짝수 편의 출발편으로
  (`KE0086 JFK/ICN` 이면 `KE0085` 는 `ICN/JFK`) 본다. 김포·부산 출발편에도 똑같이 적용된다. 대한항공 편명 규칙이라 구간은 이렇게
  맞지만 시각까지 추측하지는 않는다
- `KE35` `KE035` `KE0035` 는 같은 편으로 본다. 저장할 때도 네 자리로 맞춰 한 편으로 모은다
- 요일과 계절에 따라 시간표가 바뀌므로 실제 로스터가 언제나 우선한다

표를 넓히려면 `src/schedule.js` 의 `OUT`(나가는 편), `IN`(들어오는 편), `FULL`(양쪽 다 아는 편)에
줄을 더하면 된다.

그 위에, 구간이나 시각을 한 번이라도 넣은 편명은
`crew-cal.flights.v1` 에 적어두었다가 다음에 같은 편명이 코드만으로 들어오면 그대로 채운다.
등록한 값이 기본 시간표보다 언제나 우선한다.

- 사용자가 직접 넣은 값만 기억한다.
- 직접 넣은 값이 기억한 값보다 항상 우선한다.
- 채워 넣은 칸은 미리보기 표에 점선으로 표시하고, 몇 건을 채웠는지 알려준다.
- 근무 코드(LO, STBY 등)는 기억하지 않는다. 날마다 다른 값이기 때문이다.
- 입력 패널 아래 "편명 시각" 에서 목록을 보고 지울 수 있다.
- 같은 자리의 입력창에 아래처럼 한꺼번에 등록할 수 있다. 등록하면 **이미 넣어둔 일정에도 소급해서** 채운다.

```
KE0038  ORD/ICN  1750
KE0704  NRT/ICN  1310
```

  각 줄은 붙여넣기와 같은 규칙으로 읽으므로 `STA` 라벨이나 `+1` 도 그대로 쓸 수 있다.

## 저장
모든 일정은 브라우저 `localStorage`(`crew-cal.schedule.v1`)에 저장된다. 서버로 나가는 데이터는 없다.
그래서 같은 링크를 여럿이 써도 서로의 일정이 섞이지 않는다. 기기를 바꾸면 백업 파일로 옮긴다.
하단의 백업 내보내기 / 불러오기로 JSON 파일 왕복이 가능하다.

## 동료 의견 받기

바닥글의 **의견 보내기** 를 누르면 아래에서 창이 올라온다. 종류를 고르고 내용을 적으면
`src/feedback.js` 가 한 덩어리 글로 만들고, 내용이 채워진 채로 메일 앱을 연다.
보내는 사람은 그대로 보내기만 누르면 된다.

받을 곳은 `src/app.js` 위쪽에서 정한다.

- `MAIL_TO` — 지금 쓰는 방식. 저장소가 공개라 주소를 통짜로 두면 크롤러가 긁어가므로
  조각으로 나눠 두고 쓸 때 합친다. 기계가 훑는 걸 막는 정도이지 완전히 숨는 건 아니다.
- `OPEN_CHAT` — 카톡 오픈채팅방 주소를 넣으면 메일 대신 글을 복사하고 그 방을 연다.
- 둘 다 비우면 폰 공유 시트(`navigator.share`)로 넘기고, 그마저 없으면 클립보드로 복사한다.

- 종류가 "스케줄이 제대로 안 읽혀요" 이고 붙여넣기 탭에 글이 있을 때만
  **원문도 같이 보내기** 가 뜬다. 안 읽히는 문제는 원문이 있어야 고칠 수 있다.
- 앱 버전 · 화면 크기 · 브라우저 · 저장된 일정 수가 자동으로 붙는다.
  메일로 보내면 보내는 사람의 주소가 함께 가므로, 창의 안내 문구도 그에 맞춰 바뀐다.
- 메일 본문이 너무 길면 통째로 무시하는 폰이 있어 3000자에서 자른다.
- 글 만드는 부분은 화면과 떼어 놨으니 `test/feedback.test.js` 로 검사한다.

## 다른 사람에게 나눠주기

주소로 여는 웹 버전은 GitHub Pages 로 올라간다. 처음 한 번은 사람이 켜야 한다.
저장소 **Settings → Pages → Source** 를 **GitHub Actions** 로 두면, 그 다음부터는
`.github/workflows/pages.yml` 이 push 마다 테스트를 돌리고 배포해
`https://dy00214-eng.github.io/Crew-cal/` 이 열린다.
(워크플로의 `configure-pages` 가 Pages 를 자동으로 켜려 하지만, 기본 `GITHUB_TOKEN`
권한으로는 `Resource not accessible by integration` 이 나서 첫 설정만 손으로 해야 한다.)

받는 쪽은 가입도 설치도 필요 없고, 각자의 일정은 각자 기기에만 남는다.

웹 버전에서만 켜지는 것들:

- **홈 화면에 추가** — `manifest.webmanifest` + `icons/icon-*.png`. 아이폰은 사파리
  공유 → 홈 화면에 추가를 하면 주소창 없이 앱처럼 뜬다.
- **오프라인** — `sw.js` 가 앱 파일을 기기에 담아둬서, 두 번째부터는 비행기 안에서도 열린다.
  일정을 보여주고 새 파일은 뒤에서 받아 다음 번에 갈아끼운다.
- **동료에게 링크 보내기** 버튼 — `navigator.share`, 없으면 링크 복사.
- **처음 안내 카드** — 일정이 하나도 없을 때만 뜨고, 닫으면 `crew-cal.welcome.v1` 에 기록한다.
  바닥글의 "사용법 다시 보기" 로 다시 부를 수 있다.

한 파일로 묶은 아티팩트 버전에는 `<head>` 가 없어 manifest 링크도 없다. 앱은 그걸로
웹 버전인지 가려서(`isWebBuild()`) 위 기능들을 켜고 끈다.

아이콘을 다시 만들려면:

```bash
node scripts/make-icons.js   # icons/icon-180.png, 192, 512
```
